# MySQL 浮点类型

浮点类型用于存储带小数部分的近似数值。MySQL 常见浮点类型主要是 `FLOAT` 和 `DOUBLE`，它们适合科学计算、传感器数据、比例值等允许微小误差的场景。

## 类型范围
| 类型 | 大小 | 典型有效数字 | 非零有限值数量级 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| `FLOAT` | 4 Byte | 约 7 位十进制有效数字 | 绝对值约 `1.175E-38` 到 `3.403E+38` | IEEE 754 单精度近似值 |
| `DOUBLE` | 8 Byte | 约 15 到 16 位十进制有效数字 | 绝对值约 `2.225E-308` 到 `1.798E+308` | IEEE 754 双精度近似值 |
| `REAL` | 通常 8 Byte | 通常等同 `DOUBLE` | 受 `REAL_AS_FLOAT` SQL mode 影响 | 新 schema 优先显式写 `DOUBLE` |

范围表中的正数表示非零正规数的绝对值数量级；两种类型也能表示负数、零和次正规数。业务选型更应关注有效数字和误差传播，而不是只看最大指数。

## 近似精度
`FLOAT` 和 `DOUBLE` 保存二进制浮点近似值，不保证十进制小数完全精确。误差来自表示和后续运算，并不表示数据库“算错”。

~~~sql
CREATE TEMPORARY TABLE floating_lab (
    value_double DOUBLE NOT NULL,
    value_decimal DECIMAL(20,10) NOT NULL
);

INSERT INTO floating_lab VALUES
    (0.1, 0.1),
    (0.2, 0.2);

SELECT
    SUM(value_double) AS approximate_sum,
    ABS(SUM(value_double) - 0.3) AS absolute_error,
    SUM(value_decimal) AS exact_sum,
    SUM(value_decimal) = CAST(0.3 AS DECIMAL(20,10)) AS exact_equal
FROM floating_lab;
~~~

浮点结果比较通常使用领域容差：

~~~sql
SELECT ABS(measured_value - expected_value) <= 1e-9 AS within_tolerance
FROM measurement;
~~~

容差不能随意抄一个固定常数，应根据测量分辨率、数值尺度和误差传播定义。金额、余额、税额和需要十进制等值的结算数据使用 `DECIMAL` 或经过验证的最小单位整数。

## 显示宽度
旧写法 `FLOAT(M,D)`、`DOUBLE(M,D)` 和无符号浮点属性属于遗留/弃用方向，不应在 MySQL 8.4 新 schema 中表达业务精度。`M,D` 不是“让浮点变精确”的开关。

需要固定十进制小数位时使用 `DECIMAL(M,D)`；只需要展示固定小数位时在查询或展示层格式化。`FLOAT(p)` 也是兼容语法：较小 `p` 选择单精度、较大 `p` 选择双精度，不如直接写 `FLOAT` 或 `DOUBLE` 清晰。

## 选型建议

- 需要近似计算且空间敏感：可以考虑 `FLOAT`。
- 需要更高近似精度：优先 `DOUBLE`。
- 金额、余额、汇率结算、库存成本：使用 `DECIMAL`。
- 需要等值比较的小数：避免使用浮点类型，改用 `DECIMAL` 或整数缩放存储。
- 不确定误差能否接受时，不要默认使用浮点类型。

## 常见错误

- 用 `FLOAT` 或 `DOUBLE` 保存金额，导致计算和对账出现精度误差。
- 直接用 `=` 比较浮点字段，忽略近似值带来的微小偏差。
- 以为 `DOUBLE` 完全精确，只是比 `FLOAT` 范围更大。
- 用浮点类型保存业务编号或 ID，导致排序、比较和展示异常。
