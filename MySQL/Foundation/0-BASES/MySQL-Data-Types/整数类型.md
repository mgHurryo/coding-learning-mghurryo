# MySQL 整数类型

整数类型用于存储没有小数部分的数值。MySQL 常见整数类型按存储空间从小到大分为 `TINYINT`、`SMALLINT`、`MEDIUMINT`、`INT` 和 `BIGINT`。

## 类型范围

| 类型 | 大小 | 有符号范围 | 无符号范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| `TINYINT` | 1 Byte | -128 到 127 | 0 到 255 | 状态值、布尔标记、小枚举 |
| `SMALLINT` | 2 Byte | -32768 到 32767 | 0 到 65535 | 小范围计数、分类编号 |
| `MEDIUMINT` | 3 Byte | -8388608 到 8388607 | 0 到 16777215 | 中等规模编号，使用较少 |
| `INT` / `INTEGER` | 4 Byte | -2147483648 到 2147483647 | 0 到 4294967295 | 常用整数、普通业务 ID |
| `BIGINT` | 8 Byte | -9223372036854775808 到 9223372036854775807 | 0 到 18446744073709551615 | 大规模 ID、雪花 ID、超大计数 |

## UNSIGNED
默认整数类型是有符号的。加上 `UNSIGNED` 后不能存负数，正数上限约扩大一倍，但它不等于业务校验。

~~~sql
CREATE TABLE counter_example (
    retry_count TINYINT UNSIGNED NOT NULL DEFAULT 0,
    stock_quantity INT UNSIGNED NOT NULL,
    account_delta BIGINT NOT NULL,
    CHECK (retry_count <= 10)
);
~~~

`stock_quantity` 的存量不应为负，适合 `UNSIGNED`；`account_delta` 表示一次增减变化，必须保留负区间。若只写 `UNSIGNED` 而没有上层校验，`retry_count` 仍可写入 255，因此业务上限应由 `CHECK` 或应用规则表达。

金额可以使用 `DECIMAL`，也可以在币种小数位固定时使用最小货币单位整数，例如把人民币 10.25 元存成 1025 分。整数方案必须统一单位、处理多币种小数位并证明乘法和汇总不会溢出，不能简单断言“金额一律不能用整数”。

`BIGINT UNSIGNED` 的最大值 18446744073709551615 超过 Java `long` 上限 9223372036854775807。跨语言接口、JDBC 映射和序列化必须在选型时验证；不需要完整无符号区间时，普通 `BIGINT` 往往更省心。

在严格 SQL mode 下，越界写入会报错；关闭严格模式可能发生截断并伴随 warning。生产环境不应依赖截断行为。

## 显示宽度

旧写法里可能看到 `INT(11)`，这里的 `11` 不是存储范围，也不会让 `INT` 变成 11 位数字。整数范围只由类型和是否 `UNSIGNED` 决定。

`ZEROFILL` 会按显示宽度补零，同时隐式带上 `UNSIGNED`。新项目中不建议依赖 `ZEROFILL` 做展示格式，展示层自行格式化更清晰。

```sql
code INT(6) ZEROFILL
```

## 选型建议
- 状态、开关和很小的等级：`TINYINT`，若只能为 0/1，再增加 `CHECK`。
- 端口、短计数和明确小范围编号：`SMALLINT` 或 `SMALLINT UNSIGNED`。
- 约数百万规模且空间极敏感的编号：可评估 `MEDIUMINT`，但先确认语言和 ORM 支持。
- 普通数量和计数：常用 `INT`；预计超过约 21 亿时直接评估 `BIGINT`。
- 内部自增主键、订单量或分布式 ID：通常 `BIGINT`；是否 `UNSIGNED` 取决于客户端边界。
- 增减量、温差、余额变化等可能为负的字段：保持 signed。
- 选型使用“当前最大值 + 增长率 + 保留年限 + 安全系数”估算，不只看当前样本。

## 常见错误
- 把 `INT(11)` 理解成最多 11 位数字；它不改变 4 Byte 存储和数值范围。
- 把 `BOOL` / `BOOLEAN` 当成强布尔；它们只是 `TINYINT(1)` 别名。
- 自增主键选得过小，接近上限后才在大表上改类型。
- 把整数存为字符串，造成 `'100' < '20'` 一类词法排序和隐式转换问题。
- 对变化量误用 `UNSIGNED`，使负数成为异常或截断。
- 使用 `BIGINT UNSIGNED`，却在 Java 中直接映射为可能溢出的 `long`。
- 假设 `AUTO_INCREMENT` 连续无缺口；回滚、冲突和重启都可能留下间隔。
