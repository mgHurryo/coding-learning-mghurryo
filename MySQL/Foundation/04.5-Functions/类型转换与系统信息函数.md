# MySQL 类型转换与系统信息函数

## 类型转换

```sql
SELECT
    CAST('2026-07-20' AS DATE) AS order_date,
    CAST('123.45' AS DECIMAL(10, 2)) AS amount,
    CONVERT('abc' USING utf8mb4) AS text_value;
```

常用目标类型包括 `CHAR`、`DATE`、`DATETIME`、`DECIMAL`、`SIGNED` 和 `UNSIGNED`。显式转换比依赖隐式转换更容易阅读，也更能避免字符串和数字比较时的意外结果。

## 系统信息函数

| 函数 | 作用 |
| :--- | :--- |
| `VERSION()` | MySQL 服务器版本 |
| `DATABASE()` | 当前默认数据库，没有则返回 `NULL` |
| `USER()` | 客户端连接声明的用户 |
| `CURRENT_USER()` | 服务器用于认证和授权的账户 |
| `CONNECTION_ID()` | 当前连接 ID |
| `LAST_INSERT_ID()` | 当前连接最近一次自增 ID |
| `ROW_COUNT()` | 上一条写语句影响的行数 |

`USER()` 和 `CURRENT_USER()` 可能不同：前者描述连接请求，后者描述实际匹配到的授权账户。排查权限问题时不要混淆二者。

## 易错点与安全边界

- 转换失败可能返回 0、`NULL` 或警告，取决于目标类型和 SQL 模式；导入前应验证数据。
- 不要把 `LAST_INSERT_ID()` 当成全局值，它只对当前连接有意义。
- `ROW_COUNT()` 必须紧接着读取，否则下一条语句可能改变它的含义。
- 不要用 `USER()` 拼接权限 SQL；权限管理应使用参数绑定和明确的 DCL 操作。
