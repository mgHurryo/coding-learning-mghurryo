# 分库分表 Sharding

## 速览

分库分表用于单库单表容量、写入或运维成本接近上限时的水平拆分。它能扩展容量和写入，但会显著增加查询、事务和运维复杂度。

## 核心机制

按用户、租户、订单号、时间等维度选择分片键，将数据路由到不同库表。理想分片键要高频出现在查询条件中、分布均匀、长期稳定。跨分片 JOIN、聚合、排序、分页和事务都会变复杂。

## SQL/配置示例

```text
user_id % 16 -> user_00 ... user_15
order_id hash -> db_n.table_n
```

## 项目落地

优先通过索引、归档、读写分离、缓存、冷热拆分解决问题。只有增长趋势明确且单机方案接近边界时，再引入分库分表。

## 常见错误

不要过早分库分表；不要选会变化的分片键；不要低估全局唯一 ID、跨分片查询和数据迁移成本。
