# 运算符与表达式

## 表达式是什么

表达式由列、常量、函数和运算符组合，计算后得到一个值。它可以出现在 `SELECT`、`WHERE`、`ON`、`HAVING` 和 `ORDER BY` 等位置。

```sql

SELECT
    id,
    view_count,
    view_count * 2 AS doubled_views,
    view_count >= 1000 AS is_popular
FROM article;
```

MySQL 中布尔判断通常以 `1`、`0` 或 `NULL` 表示真、假和未知。

## 运算符速查

| 类型 | 运算符 | 说明 |
| :--- | :--- | :--- |
| 比较 | `=`、`<>`、`!=`、`>`、`>=`、`<`、`<=` | 比较两个值；SQL 标准不等于写法是 `<>` |
| NULL 安全比较 | `<=>` | 两侧都为 `NULL` 时返回真，是 MySQL 扩展 |
| 逻辑 | `NOT`、`AND`、`OR`、`XOR` | 组合或取反条件 |
| 算术 | `+`、`-`、`*`、`/`、`DIV`、`%`、`MOD` | 数值计算 |
| 范围 / 集合 | `BETWEEN`、`IN` | 范围或候选集合匹配 |
| 模式 | `LIKE`、`REGEXP` | 字符模式或正则匹配 |
| 空值 | `IS NULL`、`IS NOT NULL` | 判断 NULL |
| 存在性 | `EXISTS`、`NOT EXISTS` | 判断子查询是否返回行 |

## AND、OR 与括号

`AND` 的优先级高于 `OR`：

```sql

-- 实际含义是 status = 1 OR (status = 2 AND view_count >= 1000)
SELECT id
FROM article
WHERE status = 1
   OR status = 2 AND view_count >= 1000;
```

业务条件稍复杂时应使用括号表达意图：

```sql

SELECT id
FROM article
WHERE (status = 1 OR status = 2)
  AND view_count >= 1000;
```

## 三值逻辑

任何与 `NULL` 的普通比较通常得到未知，而不是明确的真或假：

```sql

SELECT
    NULL = NULL,
    NULL <> 1,
    NULL IS NULL,
    NULL <=> NULL;
```

`WHERE` 只保留结果为真的行，假和未知都会被排除。详见 [IS NULL 空值判断](IS-NULL-空值判断.md)。

## 隐式类型转换

```sql

-- user_id 是 BIGINT，却拿字符串比较
SELECT id
FROM article
WHERE user_id = '100';
```

MySQL 可能自动转换并返回正确结果，但混合类型会隐藏脏数据，也可能影响索引和比较语义。应用参数类型应与字段类型一致。

尤其不要将数字列与非数字字符串比较。MySQL 的转换规则可能把多个字符串转换成相同数值，引发意外匹配。

## 可索引表达式

对索引列进行函数或计算，常会让普通索引难以直接定位：

```sql

-- 不利于直接使用 create_time 的普通索引
WHERE DATE(create_time) = '2026-07-20'

-- 改为左闭右开范围
WHERE create_time >= '2026-07-20 00:00:00'
  AND create_time <  '2026-07-21 00:00:00'
```

若业务必须按表达式搜索，可评估函数索引或生成列，但应先确认查询模式。

## 常见错误

- 用 `==` 代替 SQL 的 `=`。
- 用 `= NULL` 代替 `IS NULL`。
- 混用 `AND` 与 `OR` 却不加括号。
- 依赖隐式转换来修正错误参数类型。
- 对索引列做不必要的函数、计算或类型转换。
- 直接拼接用户输入，导致 SQL 注入。参数值应通过预编译占位符绑定。
