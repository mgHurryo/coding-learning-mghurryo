# 数据库边界与业务幂等

## 速览

数据库能保证单库事务和约束，但不能自动解决所有分布式业务一致性。幂等写入要结合唯一键、状态机、事务、消息重试和补偿设计。

## 核心机制

唯一键可以防止重复插入；事务可以保证同库多表原子变更；状态字段可以防止非法流转；消息表或 outbox 可以把本地事务和异步消息关联起来。跨服务一致性通常依赖最终一致和补偿。

## SQL/配置示例

```sql
INSERT INTO payment_order(request_id, amount, status)
VALUES (?, ?, 'INIT')
ON DUPLICATE KEY UPDATE request_id = request_id;
```

## 项目落地

接口重试、支付回调、消息消费都要设计幂等键。Service 层负责业务状态判断，数据库唯一约束负责兜底。

## 常见错误

不要只靠前端防重复提交；不要只靠 Redis 锁而没有数据库唯一约束；不要在失败重试时生成新的幂等键。
