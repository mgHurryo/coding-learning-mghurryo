# MySQL 日期类型

日期时间类型用于存储日期、时间点、时长或年份。MySQL 常见日期时间类型包括 `DATE`、`TIME`、`DATETIME`、`TIMESTAMP` 和 `YEAR`。

## 类型范围

| 类型 | 大小 | 取值范围 | 备注 |
| :--- | :--- | :--- | :--- |
| `DATE` | 3 Byte | `1000-01-01` 到 `9999-12-31` | 只保存日期，不保存时间 |
| `TIME` | 3 Byte | `-838:59:59` 到 `838:59:59` | 可表示一天内时间，也可表示时间间隔 |
| `DATETIME` | 5 Byte | `1000-01-01 00:00:00` 到 `9999-12-31 23:59:59` | 保存日期和时间，不随时区转换 |
| `TIMESTAMP` | 4 Byte | `1970-01-01 00:00:01 UTC` 到 `2038-01-19 03:14:07 UTC` | 保存时间戳，会按会话时区转换 |
| `YEAR` | 1 Byte | `1901` 到 `2155` | 只保存年份，使用较少 |

## 时间精度

MySQL 日期时间类型可以指定小数秒精度，范围是 0 到 6，表示秒后最多保留 6 位微秒。

```sql
birthday DATE,
start_time DATETIME,
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
created_at DATETIME(3)
```

如果业务只关心日期，例如生日、账单日、入职日期，使用 `DATE`。如果需要记录事件发生的完整时间，通常使用 `DATETIME` 或 `TIMESTAMP`。

## 时区行为

`DATETIME` 保存的是字面日期时间，不会根据时区自动转换。写入什么时间，查询出来通常就是什么时间。

`TIMESTAMP` 会按当前会话时区写入和读取。MySQL 内部以 UTC 存储，查询时再转换为会话时区，因此它更适合记录跨时区一致的事件时间，例如创建时间、更新时间和日志时间。

```sql
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

项目中要统一数据库、应用和服务器时区配置，避免同一条数据在不同环境显示出不同时间。

## 选型建议

- 只需要年月日：使用 `DATE`。
- 需要一天内时间或时间间隔：使用 `TIME`。
- 业务本地时间、预约时间、排班时间：优先 `DATETIME`。
- 创建时间、更新时间、日志时间：可以使用 `TIMESTAMP`，但要确认 2038 年范围和时区行为。
- 需要毫秒或微秒：使用 `DATETIME(3)`、`TIMESTAMP(3)` 或更高小数秒精度。

## 常见错误

- 用字符串保存日期，导致排序、过滤和范围查询都变差。
- 混用 `DATETIME` 和 `TIMESTAMP`，却没有统一时区策略。
- 把生日、账单日这类纯日期字段设计成完整时间字段。
- 忽略 `TIMESTAMP` 的 2038 年上限，用它保存很远的未来时间。
- 在日期字段上套函数过滤，例如 `DATE(create_time) = '2026-07-14'`，导致索引难以直接利用。
