# MySQL 日期类型

日期时间类型用于存储日期、时间点、时长或年份。MySQL 常见日期时间类型包括 `DATE`、`TIME`、`DATETIME`、`TIMESTAMP` 和 `YEAR`。

## 类型范围
| 类型 | 基础大小 | 取值范围 | 核心语义 |
| :--- | :--- | :--- | :--- |
| `DATE` | 3 Byte | `1000-01-01` 到 `9999-12-31` | 纯日历日期 |
| `TIME` | 3 Byte | `-838:59:59` 到 `838:59:59` | 一天内时间或时间间隔 |
| `DATETIME` | 5 Byte | `1000-01-01 00:00:00` 到 `9999-12-31 23:59:59` | 不自动做时区转换的字面日期时间 |
| `TIMESTAMP` | 4 Byte | UTC 约 `1970-01-01 00:00:01` 到 `2038-01-19 03:14:07` | 按会话时区转换的时间点 |
| `YEAR` | 1 Byte | 1901 到 2155，另允许 0000 | 单独年份，使用较少 |

`TIME`、`DATETIME`、`TIMESTAMP` 指定小数秒精度后还会增加 0 到 3 Byte。表中的范围是常用有效范围；零日期是否可写入还受 SQL mode 控制，新系统不应使用零日期代替 NULL。

## 时间精度
`TIME(fsp)`、`DATETIME(fsp)` 和 `TIMESTAMP(fsp)` 的 `fsp` 范围是 0 到 6：

| fsp | 小数秒位数 | 额外存储 |
| :--- | :--- | :--- |
| 0 | 无 | 0 Byte |
| 1 到 2 | 0.1 到 0.01 秒 | 1 Byte |
| 3 到 4 | 毫秒到 0.1 毫秒 | 2 Byte |
| 5 到 6 | 10 微秒到微秒 | 3 Byte |

~~~sql
CREATE TABLE event_log (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    occurred_at TIMESTAMP(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    local_schedule DATETIME(0) NULL,
    elapsed TIME(3) NULL,
    business_date DATE NOT NULL
);
~~~

精度应由事件产生端和驱动实际能力决定。应用只能提供毫秒时，盲目声明 `TIMESTAMP(6)` 不会产生真实微秒信息；但统一声明可以避免后续迁移，需在契约中说明低位可能为零。

## 时区行为
`DATETIME` 保存字面日期时间，不会根据会话时区自动转换。`TIMESTAMP` 表示时间点，写入和读取时按会话时区与 UTC 转换。

~~~sql
CREATE TEMPORARY TABLE timezone_lab (
    event_ts TIMESTAMP NOT NULL,
    local_time DATETIME NOT NULL
);

SET time_zone = '+08:00';
INSERT INTO timezone_lab VALUES
    ('2026-07-20 10:00:00', '2026-07-20 10:00:00');

SET time_zone = '+00:00';
SELECT event_ts, local_time FROM timezone_lab;
~~~

切换到 UTC 后，`event_ts` 变为同一瞬间的 02:00，`local_time` 仍为 10:00。数据库、连接池和应用必须统一时区策略，并在连接建立时验证 `@@session.time_zone`。

日期范围查询使用半开区间：

~~~sql
SELECT id
FROM event_log
WHERE occurred_at >= '2026-07-20 00:00:00'
  AND occurred_at <  '2026-07-21 00:00:00';
~~~

它覆盖任意小数秒精度，也比 `DATE(occurred_at) = ...` 更利于普通 B+Tree 范围扫描。

## 选型建议

- 只需要年月日：使用 `DATE`。
- 需要一天内时间或时间间隔：使用 `TIME`。
- 业务本地时间、预约时间、排班时间：优先 `DATETIME`。
- 创建时间、更新时间、日志时间：可以使用 `TIMESTAMP`，但要确认 2038 年范围和时区行为。
- 需要毫秒或微秒：使用 `DATETIME(3)`、`TIMESTAMP(3)` 或更高小数秒精度。

## 常见错误

- 用字符串保存日期，导致排序、过滤和范围查询都变差。
- 混用 `DATETIME` 和 `TIMESTAMP`，却没有统一时区策略。
- 把生日、账单日这类纯日期字段设计成完整时间字段。
- 忽略 `TIMESTAMP` 的 2038 年上限，用它保存很远的未来时间。
- 在日期字段上套函数过滤，例如 `DATE(create_time) = '2026-07-14'`，导致索引难以直接利用。
