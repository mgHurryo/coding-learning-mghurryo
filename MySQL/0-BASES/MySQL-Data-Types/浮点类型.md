# MySQL 浮点类型

浮点类型用于存储带小数部分的近似数值。MySQL 常见浮点类型主要是 `FLOAT` 和 `DOUBLE`，它们适合科学计算、传感器数据、比例值等允许微小误差的场景。

## 类型范围

| 类型 | 大小 | 精度特点 | 大致范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| `FLOAT` | 4 Byte | 单精度，约 7 位有效数字 | 约 1.175494351E-38 到 3.402823466E+38 | 占用小，误差更明显 |
| `DOUBLE` | 8 Byte | 双精度，约 15 位有效数字 | 约 2.2250738585072014E-308 到 1.7976931348623157E+308 | 精度更高，常用近似小数 |

## 近似精度

`FLOAT` 和 `DOUBLE` 保存的是近似值，不保证十进制小数完全精确。比如 `0.1`、`0.2` 这类十进制小数在二进制浮点中可能无法精确表示。

```sql
score FLOAT,
ratio DOUBLE,
temperature DOUBLE
```

适合使用浮点类型的字段通常允许轻微误差，例如坐标、温度、评分、概率、比例和科学计算结果。金额、余额、订单价格、结算数据不要使用浮点类型，通常应使用 `DECIMAL`。

## 显示宽度

旧写法里可能看到 `FLOAT(M,D)` 或 `DOUBLE(M,D)`，其中 `M` 表示总位数，`D` 表示小数位数。新项目中不建议依赖这种写法来表达业务精度。

需要固定小数位和精确计算时，优先使用 `DECIMAL(M,D)`。

```sql
price DECIMAL(10,2)
```

## 选型建议

- 需要近似计算且空间敏感：可以考虑 `FLOAT`。
- 需要更高近似精度：优先 `DOUBLE`。
- 金额、余额、汇率结算、库存成本：使用 `DECIMAL`。
- 需要等值比较的小数：避免使用浮点类型，改用 `DECIMAL` 或整数缩放存储。
- 不确定误差能否接受时，不要默认使用浮点类型。

## 常见错误

- 用 `FLOAT` 或 `DOUBLE` 保存金额，导致计算和对账出现精度误差。
- 直接用 `=` 比较浮点字段，忽略近似值带来的微小偏差。
- 以为 `DOUBLE` 完全精确，只是比 `FLOAT` 范围更大。
- 用浮点类型保存业务编号或 ID，导致排序、比较和展示异常。
