# MySQL 整数类型

整数类型用于存储没有小数部分的数值。MySQL 常见整数类型按存储空间从小到大分为 `TINYINT`、`SMALLINT`、`MEDIUMINT`、`INT` 和 `BIGINT`。

## 类型范围

| 类型 | 大小 | 有符号范围 | 无符号范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| `TINYINT` | 1 Byte | -128 到 127 | 0 到 255 | 状态值、布尔标记、小枚举 |
| `SMALLINT` | 2 Byte | -32768 到 32767 | 0 到 65535 | 小范围计数、分类编号 |
| `MEDIUMINT` | 3 Byte | -8388608 到 8388607 | 0 到 16777215 | 中等规模编号，使用较少 |
| `INT` / `INTEGER` | 4 Byte | -2147483648 到 2147483647 | 0 到 4294967295 | 常用整数、普通业务 ID |
| `BIGINT` | 8 Byte | -9223372036854775808 到 9223372036854775807 | 0 到 18446744073709551615 | 大规模 ID、雪花 ID、超大计数 |

## UNSIGNED

默认整数类型是有符号的，可以存储负数。加上 `UNSIGNED` 后不能存负数，但正数上限约扩大一倍。

```sql
age TINYINT UNSIGNED,
view_count INT UNSIGNED,
id BIGINT UNSIGNED
```

适合使用 `UNSIGNED` 的字段通常天然不可能为负，例如年龄、数量、库存、浏览次数和自增主键。金额不要为了省空间使用整数分散表示，通常优先用 `DECIMAL`。

## 显示宽度

旧写法里可能看到 `INT(11)`，这里的 `11` 不是存储范围，也不会让 `INT` 变成 11 位数字。整数范围只由类型和是否 `UNSIGNED` 决定。

`ZEROFILL` 会按显示宽度补零，同时隐式带上 `UNSIGNED`。新项目中不建议依赖 `ZEROFILL` 做展示格式，展示层自行格式化更清晰。

```sql
code INT(6) ZEROFILL
```

## 选型建议

- 状态、开关、少量枚举：优先 `TINYINT`。
- 普通数量和业务计数：常用 `INT UNSIGNED`。
- 主键、自增 ID、分布式 ID：优先 `BIGINT` 或 `BIGINT UNSIGNED`。
- 需要排序、范围查询或作为索引列时，选择能覆盖未来增长的最小类型。
- 不要为了省几个字节把类型选得过小，溢出后的修复成本通常更高。

## 常见错误

- 把 `INT(11)` 理解成最多 11 位数字。
- 自增主键用 `INT`，但业务增长后很快接近上限。
- 用字符串保存数字，导致排序、比较和索引效率变差。
- 对可能出现负数的字段误用 `UNSIGNED`，例如账户余额变动、温度差值、库存调整量。
