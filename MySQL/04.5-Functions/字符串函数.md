# MySQL 字符串函数

## 常用函数表

| 函数 | 语法 | 作用 |
| :--- | :--- | :--- |
| `CONCAT` | `CONCAT(a, b, ...)` | 连接字符串；任一参数为 `NULL` 时结果为 `NULL` |
| `CONCAT_WS` | `CONCAT_WS(separator, a, b, ...)` | 用分隔符连接，并跳过 `NULL` |
| `CHAR_LENGTH` | `CHAR_LENGTH(str)` | 返回字符数 |
| `LENGTH` | `LENGTH(str)` | 返回字节数 |
| `LOWER` / `UPPER` | `LOWER(str)` | 转换大小写，效果受字符集和排序规则影响 |
| `TRIM` | `TRIM([BOTH] remstr FROM str)` | 去除首尾空格或指定字符 |
| `SUBSTRING` | `SUBSTRING(str, pos, len)` | 从位置开始截取字符串，位置从 1 开始 |
| `LEFT` / `RIGHT` | `LEFT(str, n)` | 取左侧或右侧 n 个字符 |
| `REPLACE` | `REPLACE(str, from, to)` | 替换所有匹配片段 |
| `LOCATE` | `LOCATE(substr, str)` | 查找子串位置，找不到返回 0 |

## 示例

```sql
SELECT
    CONCAT_WS(' ', first_name, last_name) AS full_name,
    CHAR_LENGTH(title) AS title_chars,
    LENGTH(title) AS title_bytes,
    LEFT(TRIM(title), 20) AS short_title,
    REPLACE(title, 'MySQL', '数据库') AS translated_title
FROM article;
```

中文、英文和 emoji 在 utf8mb4 下占用的字节数不同，所以“字符数”不要用 `LENGTH` 代替 `CHAR_LENGTH`。截取用户可见文本时，还要考虑多字节字符和展示宽度。

## 常见错误

- `CONCAT` 中有一个字段为 `NULL`，整列结果变成 `NULL`；需要兜底时先用 `COALESCE`。
- `SUBSTRING` 的起始位置是 1，不是 0；负数位置表示从末尾计算。
- `REPLACE` 会替换所有匹配内容，不是只替换第一次。
- `TRIM` 默认去除空格，不会自动去除所有不可见字符。

## 性能提示

对索引列使用 `LOWER`、`SUBSTRING` 或 `REPLACE` 可能使普通索引无法直接定位。需要规范化搜索时，优先统一存储格式、使用合适的排序规则，或评估生成列和函数索引。模糊查找的索引影响见 [LIKE 模糊查询](../04-Query-Methods/LIKE-模糊查询.md)。
