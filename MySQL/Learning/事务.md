# 事务

一组操作的集合, 一个不可分割的工作单位, 所有在同一个事务的操作, 要不同时成功, 要不同时失败.

### 事务的基础语法

```SQL
START TRANSACTION; # 开启事务

UPDATE account SET money = money - 100 WHERE id = 1;

UPDATE account SET money = money + 100 WHERE id = 2;

COMMIT; # 提交事务
```

如果在其中发现问题, 我们还可以通过使用 `ROLLBACK` 来回滚事务.

### 自动提交

自动提交可以通过下面的语句开启: 

```SQL
SET @@autocommit = 1;
```

关闭自动提交则修改 1 为 0.

自动提交的意义是, 在写一条普通的 SQL 语句后, 不需要直行手动 `COMMIT`, 数据库自动就 commit.
类似于: 

```SQL 
SELECT * FROM user WHERE id = 1;
```

如果关闭了自动提交, 那么需要在后面手动输入 `COMMIT` 或者这条 SQL 才会被执行. 

查询自动提交是否开启:

```SQL
SELECT @@autocommit;
```

## 事务的特性

**ACID** 四大特性:
- A: 原子性(要么成功, 要不失败)
- C: 一致性(必须使所有数据保持一致状态)
- I: 隔离性(保证事务在不收外界条件影响的环境下运行)
- D: 持久性(事务一旦提交会回滚, 对数据库中的数据印象是永久的)

## 并发事务引发的问题

**脏读** : 一个事务读到了另一个事务没有提交的数据 (业务中最难接受)
**不可重复读** : 一个事务先后读取同一条记录, 但是两次读取的数据不同
**幻读** : 一个事务中相同的条件先后查询, 发现行变化了

解决这些, 就需要引入 **隔离级别**.

## 隔离级别

隔离级别分为四种: `READ UNCOMMITED`, `READ COMMITED`, `REPEATABLE READ`, `SERIALIZABLE`.

|       隔离级别        | 脏读  | 不可重复读 |   幻读    |
| :---------------: | :-: | :---: | :-----: |
| `READ UNCOMMITED` | 可能  |  可能   |   可能    |
|  `READ COMMITED`  | 不会  |  可能   |   可能    |
| `REPEATABLE READ` | 不会  |  不会   | 标准定义下可能 |
|  `SERIALIZABLE`   | 不会  |  不会   |   不会    |

查询当前数据库的事务隔离级别: 

```SQL
SELECT @@TRANSACTION_ISOLATION
```

设置隔离级别:

```SQL
SET [SESSION|GLOBAL] 
TRANSACTION ISOLATION LEVEL
 [READ UNCOMMITED|READ COMMITED|REPEATABLE READ|SERIALIZABLE];
```

其中, `SESSION` 和 `GLOBAL` 指的是 **当前会话** 或者 **全局**.

当前会话可以理解为当前连接.

> [!warning] Warning
> 隔离级别越高, 数据一致性越好, 但是并发性能越低.

## 事务的注意事项

1. 事务不应持续过久. 事务持续过久会增加数据库开销，并可能长时间持有行锁。其他需要修改这些被锁行的 SQL 通常会进入等待，而不是立即失败；等待超时或死锁时才可能报错。普通 `SELECT` 在 InnoDB 下通常可以通过 MVCC 读取已提交的旧版本，因此一般不会被行锁阻塞。
2. 事务应按业务划分, 而不是 SQL 数量划分.
3. 死锁.
4. 索引会影响事务的范围, 需要合理设计索引.
5. 隔离级别不是越高越好, 隔离级别越高, 数据一致性上升, 但是并发自由度下降.
6. 不要滥用 `SELECT ... FOR UPDATE`, 这条语句会锁定行, 意思是, 我要读取, 将这行锁定, 后续准备修改.
7. 注意大事务. 过大的事务可能会造成 `COMMIT`  和 `ROLLBACK` 的耗时过长.
8. 异常时一定要注意 `ROOLBACK`.
9. 在框架内手写 JDBC 的时候, 一定要注意 `commit()`.
10. MySQL的 DDL 和普通的 DML 不完全相同, 在遇到 `ALTER`, `CREATE`, `DROP` 时, 可能存在隐式的提交规则/特殊的事务.
