# 存储引擎

存储数据, 建立索引, 更新/查询数据的技术的实现方式/ 存储引擎是基于表的, 而不是基于库的, 所以存储引擎也可被称为表类型.

在 MySQL 中, 默认存储引擎是 InnoDB.

## 查看存储引擎

```SQL
SHOW ENGINES;
```

## 指定存储引擎

创建表时, 指定存储引擎:
```SQL
CREATE TABLE 表名(
	字段 字段类型[COMMENT 注释],
	...
) ENGINE = INNODB [COMMENT 注释];
```


## 各种存储引擎
### InnoDB

兼顾高可靠性和高性能的通用存储引擎. 在 5.5 版本以后, 是默认的存储引擎.

#### 特点

- `DML` 操作遵循 `ACID` , 支持事务;
- 行级锁, 提高并发访问性能;
- 支持外键 `FOREIGN KEY` 约束, 保证数据的 **完整性** 和 **正确性**;

其文件为: `xxx.ibd` 其中, `xxx` 是表名. `innoBD` 引擎的每张表都会对应这样一个表空间文件, 存储改表的结构(`frm`, `sdi`), 数据和索引. 参数是 `innodb_file_per_table`.


### MyISAM

MySQL 早期的默认存储引擎.

#### 特点

- 不支持事务, 不支持外键
- 支持表锁, 不支持行锁
- 访问速度快.

一张表通常分为三个文件进行存储, 分别为 `MYD` 文件(负责存储表数据), `MYI` 文件(负责存储索引), `sdi` 文件(负责存储表结构信息).

### Memory

表存储在内存中, 只能将这些表作为临时表或者缓存使用, 不得持久化存储.

#### 特点

- 内存存放
- Hash 索引(默认)

一张表直接存储在一个 `sdi` 文件中(只存储表结构信息, 数据全部在内存中).

### 各个存储引擎的对比

|    特点    |   InnoDB    | MyISAM | Memory |
| :------: | :---------: | :----: | :----: |
|   存储限制   |    64TB     |   有    |   有    |
|   事务安全   |     支持      |   -    |   -    |
|   锁机制    |     行锁      |   表锁   |   表锁   |
| B+tree索引 |     支持      |   支持   |   支持   |
|  Hash索引  |      -      |   -    |   支持   |
|   全文索引   | 支持（5.6版本之后） |   支持   |   -    |
|   空间使用   |      高      |   低    |  N/A   |
|   内存使用   |      高      |   低    |   中等   |
|  批量插入速度  |      低      |   高    |   高    |
|   支持外键   |     支持      |   -    |   -    |
### 选择存储引擎

根据业务和应用系统的特点选择合适的引擎. 对于复杂的应用系统, 还可以根据实际情况选择多种存储引擎进行组合.

`InnoDB`: 对事务的完整性有比较高的要求, 在并发条件下要求数据的一整新, 数据操作除了插入和查询之外, 还包含很多的更新, 删除操作, 那么 `InnoDB` 合适.

`MyISAM`: 引用以读操作和插入操作维度, 只有很少的跟新和删除操作, 并且对事务的完整性, 并发性要求并不是很高, 那么 `MyISAM` 合适.

`MEMORY`: 访问速度快, 通常用于临时表和缓存, 缺陷是, 对表的大小有限制, 太大的表无法缓存在内存中, 同时无法保证 数据安全性.
