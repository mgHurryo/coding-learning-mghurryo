# 外键约束

外键用来让两张表的数据之间建立连接, 从而保证数据的一致性和完整性.

> [!caution] 注意
> 外键的局限性较大, 一般情况下完全不会使用.
>
> 1. 在大型服务中, 分库分表是必要的, 但是在分库分表后, 外键基本上无法使用. 通常关联关系是由程序统一管理.
> 2. 微服务架构中, 一个服务不应该直接依赖于其他服务的数据库.
> 3. 删除和更新可能带来额外的锁竞争, 如果使用级联删除, 在高并发系统中风险极高.
> 4. 容易出现意外的大规模操作.

## 子(从)表和父(主)表的区分

通常情况下, 在外键和外键关联键的关系中(与其他列无关), 外键列所在的表被称之为子表, 被关联的键称之为父表.

一个表既可以被称为子表也可被称为主表, 具体是看当前键是外键还是被引用的键.

## 外键标准命名方式

外键规则名: (父表名_父表列名)

> e.g.
> 父表名: users, 父列名: id
> 子表列名: users_id

> [!warning] 注意
>  1. 外键关联的列, **最好需要保持唯一**, 无论是关联自身列还是管理其他表的列.
>  2. 在删除父表的时候, 需要谨慎再谨慎, 因为会联动子表一起进行数据删除.
>  3. 外键在创建时, 子表列和父表列必须保持相同数据类型(包括UNSIGN等等).

## 使用外键

### 使用 [`CREATE`](MySQL/Foundation/02-Schema-DDL/CREATE-TABLE-创建表) 在建表时候创建外键

```SQL

CREATE TABLE a_new_table(
	子表字段名 数据类型,
	FOREIGN KEY (子表字段名) REFERENCES 父表名(父表字段名);
)
```

e.g. 需要在 `a_new_table` 表中关联 `users` 表中的 `id` 字段, 那么我应该这样写

```SQL

CREATE TABLE a_new_table(
	users_id BIGINT,
	user_name varchar(50) NOT NULL,
	FOREIGN KEY users_id REFERENCES users(id);
)
```

如果要为这个外键规则起别名, 通常采用 `fk_子表名_父表名_父表字段` 来进行

```SQL

CONSTRAINT fk_a_new_table_users_id FOREIGN KEY users_id REFERENCES users(id);
```

当然还有删除规则, 当我们删除父表中的这一行记录, 决定子表的行为

```SQL
// 一起删除
ON DELETE CASCADE
// 设为NULL(父表删除, 子表外键设为NULL, 需要注意的是, 子表的当前字段必须允许使用 NULL)
ON DELETE SET NULL
// 不允许删除(子表有数据引用, 不得删除)
ON DELETE RESTRICT
ON DELETE NO ACTION
```

使用删除规则

```SQL
// 设置外键名同时在父表记录删除时, 将子表引用的外键设为 NULL
CONSTRANINT fk_a_new_table_users_id FOREIGN KEY users_id REFERENCES users(id) ON DELETE SET NULL;
```

> [!warning] 注意
>
> 在没有设置删除规则时, 默认删除规则是 RESTRICT, 也就是说, 当父表被关联的键存在子表索引, 那么被关联的父表行是不得被删除的.


### 在建表后使用 [`ALERT`](MySQL/Foundation/02-Schema-DDL/ALTER-TABLE-修改表) 添加外键列

```SQL
ALTER TABLE a_new_table
ADD CONSTRANINT fk_a_new_table_users_id FOREIGN KEY users_id REFERENCES users(id) ON DELETE SET NULL;
```

## 删除外键

删除外键时, 需要使用外键规则名来进行删除, 如果在创建时或者修改表结构时没有写 `CONSTRANINT`, MySQL 会自动为这个规则命名, 我们需要查表来获得外检规则名, 所以一般情况下,  `CONSTRANINT` 是必要的, 否则在后面进行管理的时候会非常混乱

```SQL
// 查表获得外键规则名
SHOW CREATE TABLE a_new_table;
```

删除外键

```SQL
ALTER TABLE a_new_table
DROP FOREIGN KEY fk_a_new_table_users_id;
```
