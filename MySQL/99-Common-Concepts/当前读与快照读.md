# 当前读与快照读

## 速览

快照读读取事务可见版本，通常依赖 MVCC；当前读读取最新已提交或将要修改的记录，并可能加锁。区分二者是理解隔离级别和锁的关键。

## 核心机制

普通 `SELECT` 在 InnoDB 中通常是一致性快照读。`SELECT ... FOR UPDATE`、`SELECT ... LOCK IN SHARE MODE`、`UPDATE`、`DELETE` 属于当前读，会读取最新记录并按条件加锁。RR 隔离级别下，同一事务内快照读可能看到同一个 Read View，而当前读会检查最新版本。

## SQL/配置示例

```sql
SELECT * FROM account WHERE id = 1;
SELECT * FROM account WHERE id = 1 FOR UPDATE;
```

## 项目落地

读详情展示通常用快照读；扣库存、抢券、状态流转这类需要并发控制的场景，要在事务内使用当前读或原子更新。

## 常见错误

不要以为普通 SELECT 会阻塞写入；也不要以为所有 SELECT 都不加锁。是否加锁取决于语句类型、隔离级别、索引和执行计划。
