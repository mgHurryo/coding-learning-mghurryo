# 常用查询函数

## 使用原则

函数可以用于格式化和计算，但数据库查询的首要职责仍是正确、高效地筛选数据。展示层能完成的复杂格式化通常留给应用；对索引列使用函数前要评估可索引性。

## 字符串函数

| 函数 | 示例 | 作用 |
| :--- | :--- | :--- |
| `CONCAT` | `CONCAT(username, '-', id)` | 连接字符串；任一参数为 NULL 时结果为 NULL |
| `CONCAT_WS` | `CONCAT_WS('-', username, id)` | 使用分隔符连接并跳过 NULL |
| `CHAR_LENGTH` | `CHAR_LENGTH(title)` | 字符数量 |
| `LENGTH` | `LENGTH(title)` | 字节数量 |
| `LOWER` / `UPPER` | `LOWER(username)` | 大小写转换 |
| `TRIM` | `TRIM(username)` | 去除首尾空格 |
| `SUBSTRING` | `SUBSTRING(title, 1, 10)` | 截取字符串 |
| `REPLACE` | `REPLACE(title, '旧', '新')` | 替换字符串片段 |

`CHAR_LENGTH` 与 `LENGTH` 对多字节字符的结果不同。例如 utf8mb4 中文字符通常占多个字节，但字符数仍是 1。

## 数值函数

| 函数 | 作用 |
| :--- | :--- |
| `ABS(n)` | 绝对值 |
| `ROUND(n, d)` | 四舍五入到 d 位小数 |
| `TRUNCATE(n, d)` | 直接截断到 d 位小数 |
| `CEIL(n)` / `FLOOR(n)` | 向上 / 向下取整 |
| `MOD(a, b)` | 求余数 |

金额计算应使用 `DECIMAL`，不要依赖浮点类型得到精确小数结果。

## 日期时间函数

```sql

SELECT
    CURRENT_DATE,
    CURRENT_TIMESTAMP,
    DATE(create_time),
    YEAR(create_time),
    DATE_ADD(create_time, INTERVAL 7 DAY),
    TIMESTAMPDIFF(DAY, create_time, CURRENT_TIMESTAMP)
FROM article
LIMIT 1;
```

常见函数：

| 函数 | 作用 |
| :--- | :--- |
| `CURRENT_DATE` | 当前日期 |
| `CURRENT_TIMESTAMP` / `NOW()` | 当前日期时间 |
| `DATE_ADD` / `DATE_SUB` | 加减时间间隔 |
| `DATEDIFF` | 两日期相差天数 |
| `TIMESTAMPDIFF` | 按指定单位计算差值 |
| `DATE_FORMAT` | 格式化日期时间 |
| `STR_TO_DATE` | 按格式解析字符串 |

按日期过滤时，优先对常量计算边界，不要把索引列包在 `DATE()` 中：

```sql

WHERE create_time >= '2026-07-20'
  AND create_time <  '2026-07-21'
```

## NULL 处理函数

| 函数 | 作用 |
| :--- | :--- |
| `COALESCE(a, b, ...)` | 返回第一个非 NULL 值，标准 SQL |
| `IFNULL(a, b)` | a 为 NULL 时返回 b，MySQL 特有 |
| `NULLIF(a, b)` | a 与 b 相等时返回 NULL，否则返回 a |

```sql

SELECT id, COALESCE(nickname, username, 'anonymous') AS display_name
FROM user;
```

`COALESCE` 只改变结果表达式，不会修改表中的原始值。

## 类型转换

```sql

SELECT
    CAST('2026-07-20' AS DATE),
    CAST(view_count AS CHAR)
FROM article
LIMIT 1;
```

优先让数据以正确类型存储。若查询中频繁转换列，通常意味着模型或参数类型需要调整。

## 流程控制函数

MySQL 还提供 `IF(condition, true_value, false_value)`，但跨数据库项目更推荐标准的 [CASE 条件表达式](CASE-条件表达式.md)。

## 性能与确定性

- 列上的函数可能阻止普通索引直接定位。
- `NOW()` 在同一语句中通常保持一致，但依赖当前时间的结果会随执行时刻变化。
- 随机排序 `ORDER BY RAND()` 常需要为大量行生成随机值并排序，不适合大表抽样。
- 查询中重复出现的昂贵表达式可通过 CTE 或派生表提高可读性，但是否减少计算取决于优化器计划。
