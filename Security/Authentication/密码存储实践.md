# 密码存储实践

密码存储的目标是：即使数据库泄露，攻击者也不能轻易还原用户明文密码。

## 1. 不要明文存储密码

明文密码一旦泄露，攻击者可以直接登录系统，也可能撞库其他网站。

后端只应保存密码哈希值，并在登录时把用户输入再次哈希后比对。

## 2. MD5 的风险

MD5 是摘要算法，不适合作为现代密码存储方案。

| 风险 | 说明 |
|------|------|
| 速度太快 | 容易被 GPU 暴力破解 |
| 无盐值重复 | 相同密码生成相同哈希 |
| 彩虹表风险 | 常见密码可被预计算反查 |
| 算法过时 | 已不推荐用于密码存储 |

Big-event 使用 MD5 展示了“哈希后比对”的基本思路，但正式项目应升级为更安全的密码哈希方案。

## 3. BCrypt 与 PasswordEncoder

Spring Security 提供 `PasswordEncoder` 接口，常用实现是 BCrypt。

```java
PasswordEncoder encoder = new BCryptPasswordEncoder();
String encoded = encoder.encode(rawPassword);
boolean matched = encoder.matches(rawPassword, encoded);
```

BCrypt 的优势：

- 自动使用随机盐。
- 慢哈希，提高破解成本。
- 同一密码多次加密结果不同。
- 与 Spring Security 集成自然。

## 4. 实战注意点

- 不要自己设计密码算法。
- 不要把密码哈希打印到日志中。
- 注册时使用 `encode`，登录时使用 `matches`。
- 迁移旧 MD5 系统时可以设计渐进升级策略，例如用户登录成功后重写为 BCrypt。
