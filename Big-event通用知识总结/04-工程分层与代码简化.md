# 工程分层与代码简化

## 1. 三层架构

Spring Boot 后端项目常见分层：

```text
Controller -> Service -> Mapper -> Database
```

各层职责：

| 层级 | 职责 |
|------|------|
| Controller | 接收 HTTP 请求、参数校验、返回响应 |
| Service | 组织业务逻辑、调用数据层、处理业务规则 |
| Mapper | 执行 SQL、访问数据库 |
| POJO / Entity | 表示数据库实体 |
| DTO | 表示接口输入或输出数据 |
| Config | 放框架配置和第三方组件配置 |
| Utils | 放无状态、可复用工具方法 |

通用原则：

- Controller 不直接写 SQL。
- Mapper 不写业务规则。
- Service 是业务流程的主要承载层。
- DTO 和数据库实体不要随意混用。

## 2. Controller 层

Controller 的核心职责是“协议适配”。

它负责：

- 映射 URL 和 HTTP 方法。
- 接收请求参数。
- 触发参数校验。
- 调用 Service。
- 包装并返回统一响应。

它不应该负责：

- 直接操作数据库。
- 编写复杂业务流程。
- 处理密码加密、Token 生成等底层细节。

## 3. Service 层

Service 的核心职责是“业务编排”。

适合放在 Service 的内容：

- 注册时检查用户名是否存在。
- 登录时校验密码。
- 修改密码时验证旧密码。
- 调用工具类生成 Token。
- 调用 Mapper 完成数据读写。

通用经验：

- Service 先定义接口，再写实现类，可以降低 Controller 对具体实现的依赖。
- 业务复杂后，Service 可以继续拆分领域服务或组件。
- 事务一般也放在 Service 方法边界上。

## 4. Mapper 层

Mapper 的核心职责是“数据访问”。

适合放在 Mapper 的内容：

- 根据用户名查用户。
- 新增用户。
- 更新用户资料。
- 更新密码。

通用边界：

- Mapper 方法名描述数据操作。
- SQL 只关心数据库，不关心 HTTP。
- SQL 结果映射为 POJO，而不是直接返回给前端。

## 5. DTO 模式

DTO 是 Data Transfer Object，用于不同层或不同系统之间传递数据。

在 Web 项目里，DTO 常用于：

- 接收注册参数。
- 接收登录参数。
- 接收更新资料参数。
- 接收修改密码参数。
- 控制接口对外暴露的字段。

DTO 的通用价值：

- 避免直接暴露数据库实体。
- 可以按接口场景设计不同字段。
- 可以在 DTO 上放校验注解。
- 能减少“一个实体类到处传”的耦合。

## 6. DTO 与 POJO 的区别

| 对比项 | DTO | POJO / Entity |
|--------|-----|---------------|
| 主要用途 | 接口入参、出参、层间传输 | 映射数据库表 |
| 是否带校验 | 常见 | 通常较少 |
| 是否对应表结构 | 不一定 | 通常对应 |
| 是否暴露给前端 | 可以按需暴露 | 不建议直接暴露全部字段 |
| 字段设计依据 | 接口场景 | 数据库结构 |

通用例子：

- 注册 DTO 只需要用户名和密码。
- 用户实体可能包含 id、密码、创建时间、更新时间。
- 返回给前端的用户信息不应该包含密码字段。

## 7. 统一响应模型

统一响应模型是一种简单但实用的接口约定。

常见结构：

```text
code + message + data
```

通用收益：

- 前端不用为每个接口单独猜返回格式。
- 错误处理集中。
- 和全局异常处理天然配合。

常见设计：

- `success(data)`：成功且有数据。
- `success()`：成功但无数据。
- `error(message)`：失败并返回提示。

## 8. Lombok

Lombok 用注解在编译期生成样板代码。

常见注解：

| 注解 | 作用 |
|------|------|
| `@Data` | 生成 getter、setter、toString、equals、hashCode |
| `@NoArgsConstructor` | 生成无参构造器 |
| `@AllArgsConstructor` | 生成全参构造器 |
| `@Getter` / `@Setter` | 只生成访问器方法 |

通用价值：

- 减少重复代码。
- DTO、POJO、配置属性类更简洁。
- 配合 Jackson 反序列化时，常需要无参构造器。

通用注意点：

- `@Data` 会生成 `toString`，不要让敏感字段被日志打印出来。
- 复杂实体类中，`equals` 和 `hashCode` 要谨慎。
- 团队需要 IDE 安装 Lombok 支持，否则阅读体验会受影响。

## 9. 静态工厂方法

统一响应对象常用静态工厂方法创建实例。

```java
Result.success(data);
Result.error("用户名已存在");
```

相比直接 `new` 的好处：

- 调用语义更清晰。
- 成功和失败的默认 code、message 可以集中维护。
- 外部代码不用关心构造器参数顺序。

## 10. 可复用工程习惯

- 配置放到 `application.yml`，不要硬编码。
- Controller 只处理请求和响应。
- Service 承载业务流程。
- Mapper 只访问数据库。
- DTO 负责接口数据，POJO 负责数据库映射。
- 工具类保持无状态，避免隐藏副作用。
- 密码、Token、数据库连接等敏感信息不要写进公开笔记或仓库。
- 学习项目可以先跑通，正式项目再逐步补充日志、测试、权限细分、多环境配置。
