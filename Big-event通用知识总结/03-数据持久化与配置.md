# 数据持久化与配置

## 1. DataSource 数据源

DataSource 表示应用连接数据库所需的信息。

常见配置项：

| 配置项 | 作用 |
|--------|------|
| `driver-class-name` | JDBC 驱动类 |
| `url` | 数据库连接地址 |
| `username` | 数据库用户名 |
| `password` | 数据库密码 |

通用理解：

- Spring Boot 根据 `spring.datasource.*` 自动创建数据源。
- 数据源再被 MyBatis、事务管理等组件使用。
- 数据库密码属于敏感信息，公开笔记里不应原样暴露。

## 2. JDBC URL

JDBC URL 的通用结构：

```text
jdbc:mysql://host:port/database?param1=value1&param2=value2
```

常见组成：

| 部分 | 说明 |
|------|------|
| `jdbc:mysql://` | 使用 MySQL JDBC 协议 |
| `host` | 数据库主机 |
| `port` | 数据库端口，MySQL 默认 3306 |
| `database` | 要连接的数据库名 |
| 查询参数 | 字符集、时区、SSL 等连接选项 |

通用注意点：

- 中文内容建议明确字符集配置。
- 本地开发可以用 `localhost`，生产环境通常用数据库服务地址。
- 不同环境的地址、账号、密码应分开管理。

## 3. MySQL 驱动

Java 连接 MySQL 需要 MySQL 官方 JDBC 驱动。

通用 Maven 依赖名：

```xml
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
</dependency>
```

通用理解：

- JDBC 是 Java 访问数据库的标准 API。
- MySQL 驱动是 JDBC 标准的 MySQL 实现。
- Spring Boot 会根据依赖和配置自动装配连接能力。

## 4. MyBatis 的定位

MyBatis 是半自动 ORM 框架。

| 对比 | MyBatis | JPA/Hibernate |
|------|---------|---------------|
| 核心思路 | 开发者写 SQL | 框架根据对象关系生成 SQL |
| 优势 | SQL 可控，适合复杂查询 | 对象建模完整，基础 CRUD 快 |
| 学习重点 | SQL、映射、参数绑定 | 实体关系、持久化上下文 |

通用理解：

- MyBatis 负责把 Java 方法调用映射成 SQL 执行。
- Mapper 接口由 MyBatis 动态生成代理对象。
- 查询结果可以映射为 Java 对象。

## 5. Mapper 与 MapperScan

`@Mapper` 标记一个接口是 MyBatis Mapper。

`@MapperScan` 可以批量扫描指定包下的 Mapper 接口。

通用经验：

- 小项目可以每个 Mapper 接口都加 `@Mapper`。
- Mapper 较多时，在启动类统一配置 `@MapperScan` 更方便。
- 如果 Mapper 没有被扫描到，Service 注入时会失败。

## 6. 注解式 SQL

MyBatis 可以直接在接口方法上写 SQL 注解：

| 注解 | 作用 |
|------|------|
| `@Select` | 查询 |
| `@Insert` | 插入 |
| `@Update` | 更新 |
| `@Delete` | 删除 |

通用优点：

- 简单 SQL 写起来直接。
- 代码和 SQL 距离近，学习成本低。

通用缺点：

- SQL 复杂后注解可读性变差。
- 动态 SQL、大段 SQL 更适合 XML 或专门的 SQL 构造方式。

## 7. 参数绑定与 SQL 注入

MyBatis 中 `#{}` 是预编译占位符。

```sql
SELECT * FROM user WHERE username = #{userName}
```

通用价值：

- 底层使用类似 `PreparedStatement` 的方式绑定参数。
- 可以避免把用户输入直接拼接进 SQL。
- 是防 SQL 注入的基本做法。

注意区分：

| 写法 | 含义 | 安全性 |
|------|------|--------|
| `#{param}` | 预编译参数 | 推荐 |
| `${param}` | 字符串直接拼接 | 有注入风险，谨慎使用 |

## 8. 驼峰映射

数据库字段常用下划线命名，例如 `create_time`。

Java 字段常用驼峰命名，例如 `createTime`。

MyBatis 可以开启自动映射：

```yaml
mybatis:
  configuration:
    map-underscore-to-camel-case: true
```

通用价值：

- 表字段符合数据库命名习惯。
- Java 对象符合 Java 命名习惯。
- 减少手写映射配置。

## 9. 数据层边界

Mapper 层应该专注数据库操作。

适合放在 Mapper 的内容：

- SQL 查询。
- SQL 新增、更新、删除。
- 数据库表和 POJO 的映射。

不适合放在 Mapper 的内容：

- 密码加密。
- Token 生成。
- 复杂业务判断。
- Controller 请求处理。

这些逻辑应该放到 Service 或更合适的组件中。
